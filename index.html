Technology

A chain picks one tip. A block-DAG keeps the neighbors.

On a linear chain, two blocks found at the same moment compete and one is orphaned. A block-DAG references multiple parents, so parallel work can stay in the ledger. Ordering still has to be decided by the protocol.

Core attributes

What the design is trying to hold at once.

⚡

Throughput

More blocks can be produced in the same window because miners are not all racing for a single tip. Confirmation still depends on how the graph is ordered.

⬡

Proof-of-Work

Security is meant to come from open mining, in the Bitcoin tradition, rather than a small validator set. Hardware and hashpower still concentrate in practice.

FAQ

Straight answers.

Is this the real BlockDAG website?

No. This is a concept page built to explain the idea. The project’s public site is blockdag.network. Presale, claim, and “connect wallet” clones are a common drainer pattern — do not use this file for that.

How is a block-DAG different from Bitcoin?

Bitcoin extends one chain. A block-DAG allows several blocks to be created and referenced together. That can raise throughput, but the protocol still has to decide order and finality. Kaspa is the usual comparison for this design.

Does parallel mining remove risk?

No. Smart-contract bugs, custody, exchange liquidity, mining difficulty, and project execution risk all remain. A faster graph is not a return.
